# Azure Event Hub to SQL Server Sample

A local .NET Aspire sample application demonstrating a stock quote push pipeline across Azure Event Hubs and SQL Server (`GOOGL`, `MSFT`, `META`, and `AMZN`), including an ingestion/query API and a background persistence worker.

## Architecture Overview

* **AppHost:** Orchestrates the local Event Hubs emulator (`market-eventhubs` with the `stock-ticks` hub) and SQL Server container (`market-sql` with `marketdb`), wiring service references, readiness waits, and local transport settings.
* **Shared Domain (`Example.Common`):** Defines `StockTick`, `StockTickDto`, `TickerPriceSeriesDto`, `MarketDbContext`, and `StockTickRepository` for tick persistence and time-series queries.
* **Ingestion & Query API:** Exposes `POST /ticks/generate` to generate and publish stock tick batches (`0` to `100.00` prices) to Event Hubs, plus `GET /ticks/series` and `GET /ticks/series/{ticker}` to query ordered price series.
* **Persistence Worker:** Reads events across hub partitions and persists incoming stock ticks to SQL Server via `StockTickRepository`.

## Potential Future Improvements

* **Durable partition checkpointing:** Persist the last committed Event Hubs partition sequence number or offset alongside each saved tick in SQL Server and resume from `EventPosition.FromSequenceNumber(..., isInclusive: false)` on startup. Doing so prevents tick loss across restarts or crashes without relying on volatile in-memory buffers.
* **Batching and graceful drain:** Introduce count-and-time batching (via a coordinated channel/flusher or an Rx.NET `Buffer` stream) to reduce per-tick database round-trips under higher throughput. Ensure upstream partition readers complete cleanly on shutdown and flush any remaining buffered or in-flight ticks before the host exits.
* **Entra ID authentication and multi-instance scaling:** Configure `FullyQualifiedNamespace` with `DefaultAzureCredential` or Managed Identity for cloud environments instead of shared-key connection strings. When scaling past a single worker instance, adopt `EventProcessorClient` with a durable checkpoint store to coordinate partition leasing across replicas.
* **Richer time-series querying and idempotency:** Expand the series endpoints with validation, pagination, or aggregation windows to support FinTech charting and analytics workloads. Pair checkpointed or retried writes with idempotency safeguards so at-least-once replays do not create duplicate tick records.
